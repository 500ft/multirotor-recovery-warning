# Contributing

Changes to this project must preserve the link between requirements,
engineering data, executable gates, and safety documentation.

## Development setup

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Checks

```bash
python -m unittest discover -s Analysis/tests -v
```

Run the relevant analysis entry point when changing a model and include its
regenerated data and figures in the same commit.

## Engineering-data changes

- Keep units in every CSV header or adjacent documentation field.
- Update the requirement, interface, budget, or FMEA row before changing a gate
  that depends on it.
- Do not replace catalog estimates with measured values until the measurement
  source and procedure are recorded.
- Do not hand-edit plots or tables generated by `Analysis/` and
  `Analysis/matlab/` scripts. Python writes the plotted values; MATLAB draws them
  ([how to redraw](Analysis/matlab/README.md)).
- Quote paths containing spaces in shell commands.

## Safety changes

Do not weaken a propulsion, release-rig, guard, or flight gate to make a current
simulation pass. A threshold change needs an engineering reason, an updated
requirement, and a matching test change.

## Pull requests

Describe the affected requirement or gate, list the analysis and tests run, and
state whether each reported input is a catalog value, estimate, simulation
output, or measurement.
