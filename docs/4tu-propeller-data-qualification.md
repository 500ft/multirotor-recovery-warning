# 4TU propeller-damage source qualification

**Result:** the [versioned 4TU archive](https://doi.org/10.4121/308d8c70-cc88-45fb-b16a-5bd80531beef.v2) is reusable for a narrowly framed, descriptive study of recorded rotor response to propeller damage. It is ineligible for the roadmap's recovery-warning comparison. The inspected metadata and [published methods](https://pmc.ncbi.nlm.nih.gov/articles/PMC13342939/) do not provide independently timed recovery-failure outcomes or independent battery-pack identities. This is a source eligibility result, not a warning result. The [machine-readable audit](../Data/4tu-qualification/results.json) holds the counts, values and source hashes.

## Sources and reproduction

The source archive is *Raw data: Propeller damage induced quadrotor loss of control*, version 2, by Jasper van Beers and colleagues. Its [DataCite record](https://api.datacite.org/dois/10.4121/308d8c70-cc88-45fb-b16a-5bd80531beef) grants [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) reuse. The archive's [README](https://data.4tu.nl/file/308d8c70-cc88-45fb-b16a-5bd80531beef/0a7722bf-2980-4563-a227-8ace5b094d9f) and [ZIP](https://data.4tu.nl/file/308d8c70-cc88-45fb-b16a-5bd80531beef/3506316c-3911-4036-80a7-fa66abfae747) are linked from the versioned landing page. Source metadata snapshots in [`Data/4tu-qualification/source/`](../Data/4tu-qualification/source/) retain original filenames, plus the ZIP central-directory listing and DataCite response. These are attributed to the dataset authors under CC BY 4.0. No flight time series or full archive is copied here. The ZIP manifest is a central-directory inventory; its hash pins this inspection, not the full archive bytes. The paper is [van Beers et al., PNAS](https://doi.org/10.1073/pnas.2608847123). The separate [author code](https://github.com/Jaspervbeers/ews_for_loc/tree/7a7c2e241999149eeaef59d509159e2c47812559) uses a BSD-3-Clause license; no author code is redistributed here.

Run `python3 Analysis/qualify_4tu_metadata.py` from the repository root to regenerate the audit. The result includes SHA-256 values for every inspected metadata snapshot. The ZIP manifest lists onboard CSVs and metadata files; it contains no separate outcome-annotation file. This inventory does not exclude labels held outside the published archive.

## Eligibility matrix

| Requirement | Primary-source observation | Disposition |
| :--- | :--- | :--- |
| Reuse and version | DataCite identifies version 2 and CC BY 4.0. The archive README describes the autonomous DragonFly and manually flown HoverFly. | Qualified for attributed metadata analysis. |
| Motor command and speed | The README calls DragonFly `motor[0..3]` unitless commanded speed on a 0–2000 scale and `omega[0..3]` filtered ESC rotor speed in rad/s. `omegaUnfiltered` is its raw counterpart. HoverFly `debug[0..3]` is ESC electrical RPM, which needs a pole-pair conversion before mechanical RPM use. | Channel meanings are documented. None measures maximum available thrust or a calibrated damage-specific thrust curve. |
| Voltage and current | DragonFly `vbatLatest` is in V; `amperageLatest` is an estimated current in A. HoverFly lists corresponding voltage/current fields. | Descriptive electrical channels only. Calibration and pack identity are absent. |
| Time and motion capture | DragonFly logs `timeUs`, `timeMs`, `timeS` and external `extTime` in seconds. The README identifies `pos`/`extPos`, `vel`/`extVel` and `extAtt` as motion-capture quantities. The paper says the DragonFly ESC speed was logged at 1,000 Hz, filtered at 100 Hz and downsampled to 500 Hz for its analysis; the HoverFly logging rate was 500 Hz. | Column units and published processing are documented. Native monotonicity, dropped samples, clock alignment and effective bandwidth remain unverified because no flight arrays were read. The log's `Has OT data` flag cannot establish whether embedded external-pose fields are populated. |
| Vehicle configuration | The README names Indiflight for DragonFly and Betaflight for HoverFly, and warns that config inertia is inaccurate. DragonFly's log records Indiflight while its config names BetaFlight. The log `Mass` and config `mass` values disagree, and neither field supplies an explicit unit or weighing convention. The config contains rotor mapping and geometry. | Mass, deployed controller revision and inertia cannot be admitted to a physics model from these files. |
| Damage and outcomes | `FIDINFO.json` records damage severity and location by flight ID. DragonFly's LOC type/start/end columns are empty throughout its flight log. The paper describes completed flights without crashes, with flyaways for some conditions and illustrative videos. No separately timed outcome annotations appear in the inspected archive directory or paper methods. | Damage condition is a source label; per-flight recovery failure and lead-time endpoints are unavailable. Do not infer onset from the AC1 warning signal or substitute damage grade for failure. |
| Unseen conditions | DragonFly's battery entry records `6S`, a category; no unique pack ID is recorded. Controller, maneuver, damage and wind conditions differ. | Cannot assess unseen-pack recovery outcomes or a matched-false-alarm warning comparison. |

The published study asks whether critical-slowing-down indicators rise as propeller damage approaches instability. Its reported flyaways show that instability occurred in some conditions, but the archived flight log does not pair each included run with independently timed failure or recovery labels. The authors' AC1 processing is itself the signal one might evaluate, so it cannot define its own target event. Recorded RPM also says nothing about spare physical thrust without a calibrated command-to-force and saturation measurement.

**Next step:** keep this archive available only for a separately registered descriptive component-data question, if the owner later requests one. It cannot fill the roadmap's physical propulsion qualification or warning-outcome gate. No development flight arrays, reserved cases, classifier, fit or recovery envelope were opened or generated in this qualification. The hardware access decision remains open.
